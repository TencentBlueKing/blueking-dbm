## 根因判断

- Master 延迟 < 0.14ms 排除 Compaction（Compaction 时 Master CPU 和延迟均会显著升高）
- 慢日志命令以磁盘读（get/hget/hgetall）为主，符合冷数据读取 IO 争抢特征
- 告警触发机制：`192.168.2.28` 等节点历史尖刺被纳入集群聚合 p95 计算，超过 512ms 阈值
- 尖刺持续时间极短（< 1 分钟），自行恢复，属于正常业务高峰期瞬时 IO 压力

## 后续建议

1. 观察是否重复出现（每日 15:50 前后是否固定出现 → 可能是定时任务触发冷读）
2. 业务侧排查 `common_cloud_setting`、`wx:mm:rpi`、`sq:mm:rpi` 等 Key 的访问模式
3. 评估 `hgetall` → `hget` 按字段改造（hgetall 读整个 Hash 是最重的磁盘 IO）
