# Proxy 机型不均衡导致系统性延迟分层

**集群**: rediscluster-2.example.db  
**类型**: PredixyRedisCluster  
**日期**: 2026-07-14  

## 现象

4 台 Proxy 按机型分成两组，延迟差异显著：

| 机型 | Proxy IP | avg延迟 | latest延迟 |
|------|----------|---------|------------|
| SA3.LARGE16 | 192.168.2.50 | 186ms | 188ms |
| SA3.LARGE16 | 192.168.2.51 | 1722ms | 1449ms |
| S5.LARGE16 | 192.168.2.22 | 1235ms | 1500ms |
| S5.LARGE16 | **192.168.2.21** | **7830ms** | **5913ms** |

SA3（新一代 ARM）整体延迟低于 S5（经典 x86），符合硬件性能差异预期。

## 关键区分

- **机型分层 ≠ 单 Proxy 异常**：192.168.2.22（S5）延迟 1235ms 是"机型基准偏高"，而 192.168.2.21（S5）延迟 7830ms 是"叠加额外异常"
- 同机型内差异 6x（1235 vs 7830）远超机型间差异（SA3基准~186ms vs S5基准~1235ms = 6.7x）
- 但 192.168.2.51（SA3）也有 1722ms，说明可能有区域性因素叠加

## 诊断结论

- 后端 Master 全部正常（10~11ms），排除存储层
- 所有命令在 192.168.2.21 上均慢（全命令 30~60x），非特定命令问题
- QPS/连接数无异常，排除流量不均
- CPU 3.4%，不足以解释延迟
- **192.168.2.21 延迟持续恶化**（14:00 2468ms → 15:53 10270ms），是进程/资源级问题

## 建议模式

1. 优先排查异常 Proxy 进程状态（考虑重启）
2. 次优先：机型统一（S5 → SA3 替换）
3. 长期：Proxy 扩容或连接分布优化
