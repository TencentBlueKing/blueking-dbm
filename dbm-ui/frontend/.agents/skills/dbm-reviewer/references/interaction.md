# 交互一致性检查项

回答的问题：同类操作在这次改动里的表现和反馈，是否与项目既有页面一致。改了模板、样式、弹层、提示、表单时读。

判断依据是 `dbm-designer` skill 与同类页面的既有做法，规范内容不在本篇重复。本篇只管审查时比什么、怎么比。

## 怎么比

- 先找参照物：同一模块里最接近的页面或组件（同类列表页、同类提单页、同类弹窗），读它怎么做，再看 diff 是否一致；
- 判据是「用户做同一类事得到同一种反馈」，不是代码写法相同；
- 找不到参照物，或既有页面之间本身就不一致时，不立项，写进「待人工验证」并说明两种做法分别在哪。

## 比什么

- 操作反馈：成功、失败各自有没有提示，提示形态与同类操作一致，有没有同一件事提示两次；
- 确认：同等危险程度的操作确认形态一致；危险操作有确认，普通操作没有多余的确认；
- 加载与禁用：提交中、加载中有没有状态；禁用时有没有说明原因；无权限与禁用的表现有没有区分；
- 空值与空态：空值占位、空列表、搜索无结果的表现与同类页面一致；
- 表单：校验时机、报错位置、必填标记、重置行为与同类表单一致；改过内容后离开有没有确认；
- 弹层：再次打开是否残留上次的输入；关闭方式与同类弹层一致；关闭后来源列表是否按需刷新；
- 列表：筛选、分页、排序、刷新之后，选中项与页码的保持方式与同类列表一致；
- 文案：同一概念同一叫法，按钮文案与同类操作一致；
- 操作后的落点：成功后是停留、关闭还是跳转，与同类操作一致。

## 定级

- 交互不一致默认 P2 / P3；
- 导致用户得不到反馈（操作失败无提示）、误操作不可逆（危险操作无确认）、未保存内容丢失的，按逻辑 bug 定级，可到 P1。
