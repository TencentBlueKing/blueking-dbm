# 性能检查项

回答的问题：这次改动会不会让页面明显变慢或变卡。改动涉及列表 / 表格渲染、监听器、大数据量、路由或重型组件引入时读。

性能问题要能说出数据量级或触发频率（多少行、多高频）才立项，说不出就不报；纯理论上的「可以更快」不报。

## 响应式开销

- 大数组、大对象只做整体替换，却放进深层响应的 `ref` / `reactive`，应用 `shallowRef`；
- 图表、编辑器等第三方实例被放进响应式状态，应用 `shallowRef` 或 `markRaw`；
- 无必要的 `{ deep: true }` 监听大对象。

## 渲染

- 模板里调用方法做重计算，每次渲染都会执行，应改 `computed`；`v-for` 里对每一行调用昂贵函数同理；
- 数据量没有上限的列表、表格既不分页也不虚拟滚动；
- 高频切换显隐的大块内容用 `v-if`，每次都重建，应用 `v-show`；
- 输入、滚动、窗口缩放这类高频事件里直接发请求或做重计算，没有防抖 / 节流。

## 请求与加载

- 循环里串行 `await` 彼此无依赖的请求，应并行；
- 每行各发一个请求（N+1），应改批量接口或在父层一次取回；
- 路由组件、重型组件（编辑器、图表、大弹窗）同步引入，没有懒加载；
- 引入方式与项目既有做法不一致，把整个库打进了首屏包。项目本来就整包引入的库不要报（如 `import _ from 'lodash'`）。
