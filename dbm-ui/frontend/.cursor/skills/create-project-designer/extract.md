# 探查与提取

## 五类信息源

按顺序定位，每类都要找到才能保证数值完整。

| # | 信息源           | 提供什么                                       | 找法                                                         |
| - | ---------------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 1 | 全局框架布局     | 顶栏/侧栏/面包屑/内容区的高宽、背景、内边距    | 搜索布局目录、外层壳组件、包含 `100vh` 或 `calc(100vh` 的样式 |
| 2 | 设计变量文件     | 色板、字号、圆角的语义命名与取值               | 搜索 variables / tokens / theme 类样式文件                    |
| 3 | 全局重置与原子类 | body 字体栈与基准字号、间距原子类、滚动条      | 搜索 reset / base / common 类样式文件                         |
| 4 | UI 组件库产物    | 组件的**基础**尺寸（行高、图标列宽、状态色）   | 依赖包内已编译的 CSS 产物                                     |
| 5 | 图标与图片资源   | 图标字体或图标集、logo                         | 搜索 `@font-face`、图标组件、images 目录                      |

## 关键技巧：基础值在组件库产物里

项目自己的样式文件通常只是**覆盖层**，只看它会得到不完整甚至失真的值。组件的真实基础尺寸在依赖包的编译产物 CSS 里。

压缩成单行的产物 CSS 用正则按规则块提取，逐个 class 拿完整声明：

```bash
rg -o '\.<class-前缀>[^{]*\{[^}]*\}' <依赖包>/dist/style.css | sort -u
```

拿到基础值后，再叠加项目样式里的覆盖，得到最终生效值。两处冲突时以覆盖层为准。

## 提取维度

对每个维度，先穷举出现过的值，再判断是否收敛。

| 维度       | 提取内容                                             | 归纳目标                             |
| ---------- | ---------------------------------------------------- | ------------------------------------ |
| 间距       | margin / padding / gap 的全部取值                    | 收敛成有限集合，指出禁止的中间值     |
| 字号       | 全部 font-size                                       | 通常只有 3 档，标注哪档是内容区基准  |
| 色板       | 色值 + 其语义用途                                    | 语义 → 色值 → 用途 三列对照          |
| 固定高度   | 顶栏、面包屑、底部操作栏、表格行、菜单项、分页栏      | 逐项写死                             |
| 宽度档位   | 侧滑、弹窗、搜索框、各列宽                            | 按档位列出并标注默认档               |
| 圆角与边框 | border-radius、分割线色                              | 通常全站唯一值                       |
| 状态样式   | hover / active / disabled / error 的底色与字色        | 按状态列出                           |

## 归纳收敛规律

数值提取完要做一次收敛判断，这是规范的价值所在：

- 若间距只出现 8 / 16 / 20 / 24，就明确写「间距只有这四个值，不要出现 10 / 12 / 18」
- 若字号只出现 12 / 14 / 16，就写清每档的适用场景，并指出全局默认值与内容区实际基准的差异
- 若某个主题色只在极少数位置出现（如危险色仅用于删除、终止），把这种稀缺性本身写成规范：「保持稀缺，稀缺性即语义」

## 页面骨架归纳

扫描页面目录，按「顶层结构 + 底部操作」两个特征聚类，通常能收敛到 3–5 类。产出一张判定表：

| 骨架   | 判定条件         | 顶层结构             | 底部操作       |
| ------ | ---------------- | -------------------- | -------------- |
| 列表页 | 展示可筛选的集合 | 操作区 + 表格 + 分页 | 无，操作在行内 |
| ...    | ...              | ...                  | ...            |

聚类后必须回头验证：随机抽查若干现有页面，确认都能归入某一类。有页面归不进去，说明骨架划分不完整，补一类或调整判定条件。

## 交互流程提取

规范里最有价值的部分是流程分支，不是静态样式。重点提取：

- **提交流程**：校验 → 提交 → 成功怎么处理（跳转还是原地清空）→ 失败在哪里提示 → 特殊错误码（如重复提交）走什么交互
- **错误提示层级**：字段级、页面级、行级各在什么位置、由什么触发
- **离开拦截**：有几种状态、分别什么行为
- **危险操作确认**：确认强度（是否要求输入名称）、按钮文案、内容排版
- **消息反馈**：各场景的时长与是否可手动关闭

这些用编号流程或决策树表达，把分支写全。
