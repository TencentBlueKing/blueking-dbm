# 去项目化转译与文档撰写

## 转译对照

提取阶段拿到的是带项目标识的原始信息，写入文档前逐类转译。

| 原始信息类型     | 处理方式               | 示例                                                                |
| ---------------- | ---------------------- | ------------------------------------------------------------------- |
| 文件路径         | 删除                   | 「参考实现：src/layout/Index.vue」→ 整节删除                        |
| 组件名           | 换成形态描述           | `SmartAction` → 底部固定操作区；`DbSideslider` → 侧滑面板            |
| CSS class        | 换成数值               | `class="w-88"` → min-width 88px；`mr-8` → 间距 8px                  |
| 样式变量名       | 换成语义 + 色值        | `@primary-color` → 主色 #3a84ff                                     |
| hook / 工具函数  | 换成规则本身           | `useTableSettings` → 列显隐持久化到服务端用户偏好                   |
| 国际化函数       | 换成要求               | 文案包 `t()` → 所有文案必须走国际化                                 |
| 代码统计         | 换成规范表述           | 「danger 全站仅 11 处」→ 「危险色保持稀缺，稀缺性即语义」            |
| 技术栈实现细节   | 删除或抽象             | 「路由 meta 的 isMenu 字段无消费方」→ 若无设计含义则删除            |

保留的只有四类：**数值、结构、判定条件、交互流程**。

判断标准：把这段话给一个从没见过该项目、技术栈也不同的人看，他能否照着做出符合规范的页面。能，就保留；需要他去翻代码才懂，就是没转译干净。

## 文档结构

### SKILL.md 骨架

```markdown
---
name: <项目>-frontend-design
description: >-
  <项目> 前端的排版与交互设计规范，包含设计令牌（间距、字号、颜色）、
  <N> 类页面骨架的判定与实现范式、<各场景> 的具体取值。
  新建或修改页面、组件、样式时使用，
  或当用户询问页面布局、容器留白、按钮规范、弹窗宽度、字号配色、交互模式时使用。
---

# <项目> 前端排版与交互规范

本规范只沉淀可复用的设计取值与交互模式，不涉及具体项目的组件实现。

**动手前先按场景读对应参考文件**，本文件只放每次都必须遵守的内容。

## 场景路由
<表格：要做的事 → 读哪个文件>

## <N> 类页面骨架
<判定表；并声明「新页面必须归入其中一种，不要发明第 N+1 种」>

## 设计令牌
### 间距只有 ...
### 字号只有 ...
### 颜色
<语义 / 色值 / 用途 三列>

## 全站铁律
<编号列表，每条一句话，加粗关键约束>

## 自检清单
<复选框列表，可逐条核对>
```

### 场景文件划分

按项目实际页面原型划分，一个原型一个文件。不要照搬别的项目的文件名，先归纳再命名。

每个场景文件的通用结构：

1. 一句话定位（尤其要写清**常见误解**，例如「详情页不是左右两栏」）
2. 标准骨架（ASCII 结构图，标注各段间距）
3. 关键数值表（尺寸、色值、档位）
4. 交互流程（分支写全）
5. 该场景的专属约定

## 写法要求

- **ASCII 树表达层级**，每层直接写死尺寸与色值，末尾附推导结论
- **判定用表格，决策用决策树**，避免散文
- **数值就近写**，不要让读者跨文件查一个像素值
- **表格单元格只放结论**，解释放在表格前后的句子里
- **同一概念术语统一**，选定一个叫法后全文一致

## 反模式

| 反模式               | 问题                       | 改法                             |
| -------------------- | -------------------------- | -------------------------------- |
| 「参考实现」章节     | 全是文件路径，脱离项目失效 | 整节删除                         |
| 复制别项目的场景划分 | 与本项目页面原型不匹配     | 先归纳本项目原型再命名           |
| 罗列多种可选做法     | 使用者无法决策             | 给唯一默认值，特例单独列         |
| 时效性表述           | 很快过期                   | 改成「当前做法 / 旧做法」两段    |
| 为扩展性预留抽象     | 规范描述事实，不做设计     | 删除                             |
