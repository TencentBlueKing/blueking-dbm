# 2026-11-11 容灾按可用区改造（分支 feat_bk_cloud_zone）

需求：`~/Desktop/容灾要求按可用区改造需求文档.txt`；缺口清单：`~/Desktop/cloud_zone_migration_todo.md`；
v2 申请协议：`~/Desktop/资源申请API-v2-使用说明.md`（资源池服务同批上线）。

## 已确认决策
- 资源申请开关：env `DBM_RESOURCE_APPLY_API_VERSION`，默认 v1；前后端 + 资源池三方一起上线时置 v2。
- 单据 details 的 location_spec 保留老 key（city + sub_zone_ids），只在下发前转换。
- 前端部署页已改选可用区：`sub_zone_ids` 里放可用区字符串，随机传 `[]`；「地域」仍传城市名。
- 资源池列表搜索直接透传 `bk_cloud_region` / `bk_cloud_zone`（不做转换，资源池 list 接口同批支持）。
- Cluster.bk_cloud_region 由**后端**在集群落库时补齐，前端不额外传。

## 关键实现
- `db_services/dbresource/apply_protocol.py`（新）：v1 把可用区反展开成园区 ID + 补 city；
  v2 转 bk_cloud_region / bk_cloud_zone_list / affinity_dimension=bk_cloud_zone，随机补 2 区，
  current_hosts 补可用区。所有 resource_apply 调用点走 `apply_resource()`。
- A 组 10 处容灾判定切可用区（base_validate / spider 加减切换 / mysql proxy 缩容 / tendb spider 缩容 /
  mongo 缩容校验 / mongo 选机 / autofix gates+discover）；host 字典 key 统一 `bk_cloud_zone`。
- `city_map.resolve_cloud_region(cloud_zones, city)` + `Cluster.save()` 插入时补 bk_cloud_region。
- `common/base.cluster_location_spec()` 统一给 location_spec 带 bk_cloud_region，v2 不用再反查。
- 补货支持 region+可用区下单（serializer / HCM client / flow kwargs / 原子节点）；水位带可用区与「可用区信息缺失」。
- 资源池列表/导出加可用区列、地域导出 region；实例/机器/污点池补 bk_cloud_region 字段与筛选。
- 文案：跨机架、每个可用区尽量均匀分布。
