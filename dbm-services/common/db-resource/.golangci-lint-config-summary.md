## 🎯 优化内容

### 1. 配置结构优化

采用清晰的模块化结构，包含以下主要部分：

```yaml
linters-settings:     # Linters 详细配置
linters:              # Linters 启用/禁用配置
run:                  # 运行时配置
issues:               # 问题过滤配置
output:               # 输出格式配置
severity:             # 严重程度配置
```

### 2. 启用的 Linters (28个)

#### 代码质量检查 (9个)
- `gofmt` - Go 代码格式化检查
- `gofumpt` - 更严格的 gofmt
- `goimports` - 导入排序和格式化
- `gci` - 导入排序和分组（更强大）
- `govet` - Go 官方静态分析
- `staticcheck` - 高级静态分析
- `gosimple` - 简化代码建议
- `unused` - 未使用代码检查
- `typecheck` - 类型检查

#### 代码风格检查 (4个)
- `revive` - 快速的代码风格检查器
- `gocritic` - 高度可配置的代码检查器
- `whitespace` - 空白检查
- `misspell` - 拼写错误检查

#### 代码复杂度检查 (3个)
- `funlen` - 函数长度检查 (≤80行)
- `gocyclo` - 圈复杂度检查 (≤20)
- `goconst` - 常量检查

#### 错误处理检查 (2个)
- `errcheck` - 错误检查
- `ineffassign` - 无效赋值检查

#### 资源泄漏检查 (3个)
- `bodyclose` - HTTP response body 关闭检查
- `sqlclosecheck` - SQL rows/stmt 关闭检查
- `rowserrcheck` - SQL rows.Err() 检查

#### 其他实用检查 (7个)
- `lll` - 行长度检查 (≤120字符)
- `predeclared` - 预声明标识符检查
- `unparam` - 未使用参数检查
- `unconvert` - 不必要的类型转换检查
- `dupl` - 重复代码检查
- `nolintlint` - nolint 指令检查
- `gosec` - 安全检查

### 3. 关键配置参数

#### 函数复杂度
```yaml
funlen:
  lines: 80           # 函数最大行数
  statements: 80      # 函数最大语句数

gocyclo:
  min-complexity: 20  # 最大圈复杂度
```

#### 代码风格
```yaml
lll:
  line-length: 120    # 最大行长度

goconst:
  min-len: 2          # 最小字符串长度
  min-occurrences: 2  # 最少出现次数
```

#### 导入排序
```yaml
gci:
  sections:
    - standard        # 标准库
    - default         # 第三方库
    - prefix(dbm-services)  # 本地包
```

### 4. 问题过滤优化

#### 白名单机制
启用了 15 个默认排除规则的白名单，确保不会遗漏重要问题：
- EXC0002 ~ EXC0015

#### 智能排除规则
- **测试文件**: 放宽 `funlen`、`gocyclo`、`goconst`、`dupl`、`gosec`
- **生成文件**: 跳过所有 linter 检查
- **第三方库**: 排除 `pkg/mod/` 下的文件
- **Main 函数**: 放宽 `funlen` 和 `gocyclo`
- **特殊场景**: `sync.Pool`、`go:generate`、`context.TODO()` 等

### 5. 输出配置优化

#### 结果排序
```yaml
sort-results: true
sort-order:
  - linter       # 按 linter 排序
  - severity     # 按严重程度排序
  - file         # 按文件排序
```

#### 输出格式
- **默认格式**: `colored-line-number` (带颜色的行号)
- **支持格式**: json, junit-xml, github-actions, checkstyle 等
- **去重**: `uniq-by-line: true` (同一行只报告一次)

### 6. 严重程度分级

```yaml
severity:
  rules:
    - linters: [dupl, goconst]
      severity: warning      # 重复代码和常量提取为警告
    - linters: [lll]
      severity: info         # 行长度为信息级别
```

## 📚 使用指南

### 基本使用

```bash
# 检查所有代码
golangci-lint run

# 自动修复部分问题
golangci-lint run --fix

# 只检查特定文件
golangci-lint run internal/config/config.go

# 只检查新代码
golangci-lint run --new-from-rev=HEAD~1
```

### 高级用法

```bash
# 生成 JSON 报告
golangci-lint run --out-format=json > report.json

# 生成 Checkstyle 报告（CI/CD）
golangci-lint run --out-format=checkstyle > checkstyle.xml

# 详细输出
golangci-lint run -v

# 打印资源使用情况
golangci-lint run --print-resources-usage

# 快速检查（只运行快速 linters）
golangci-lint run --fast
```

### 集成到 Git 工作流

```bash
# 提交前检查（只检查修改的文件）
git diff --name-only --diff-filter=ACMR | grep '\.go$' | xargs golangci-lint run

# 增量检查（只检查相对于 main 分支的新代码）
golangci-lint run --new-from-rev=origin/main
```

## 🔧 常见问题

### Q1: 如何临时禁用某个 linter？

```bash
# 命令行方式
golangci-lint run --disable=lll,dupl

# 代码中使用 nolint 注释
//nolint:lll // 这行代码太长，但是必须保持
longVariableName := "very long string..."
```

### Q2: 如何只检查特定的 linter？

```bash
# 启用特定 linters
golangci-lint run --enable=errcheck,unused

# 或者修改配置文件的 linters.enable 部分
```

### Q3: 如何处理误报？

```bash
# 方法1: 使用 exclude-rules (推荐)
# 在配置文件中添加排除规则

# 方法2: 使用 nolint 注释
//nolint:staticcheck // SA6002: sync.Pool with slice is intentional
pool.Put(buf)
```
